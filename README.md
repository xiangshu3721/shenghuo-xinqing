# 生活与心情小调查

花 2～3 分钟，了解一下最近的生活状态。面向 50～70 岁，手机上点选即可，没有标准答案，也不用登录、不用打字。

这不是医疗或诊断工具。页面和结果只给出温和的生活反馈，不显示分数。

## 线上页面

静态文件在 `main` 根目录。到仓库 Settings → Pages，Build and deployment 选择 Deploy from a branch，分支选 `main`，文件夹选 `/ (root)`，保存。

发布地址：

https://xiangshu3721.github.io/shenghuo-xinqing/

当前自动化令牌没有 Pages 管理权限，需要在上面的设置页手动打开一次。

本地预览：

```bash
python3 -m http.server 4173
```

然后用手机或浏览器打开 http://127.0.0.1:4173/ 。

## 目录

| 文件 | 作用 |
| --- | --- |
| `index.html` | 欢迎、答题、结果三个画面 |
| `css/style.css` | 米白 / 墨绿 / 暖金，大字号、大按钮 |
| `js/content.js` | Q1～Q15 文案与选项 |
| `js/scoring.js` | 六维、核心需求、用户类型、跟进、内部标记、需求总结 |
| `js/submit.js` | 组装数据；按配置送往飞书；始终可完成本地结果 |
| `js/config.js` | 飞书 Webhook 或多维表格配置，默认留空 |
| `js/app.js` | 点选流程 |

改过 `css/` 或 `js/` 后，把 `index.html` 里的 `?v=` 数字加一，避免手机继续用旧文件。

## 如何填写

1. 欢迎页点「开始」。大约 3 分钟。
2. 单选题点一下就会往后走。点错了，点「上一题」。
3. 最后一题最多选 3 项。「暂时都不需要」会清掉其他项。选完点「选好了」。
4. 结果页是短短几句话。想重来，点「再填一次」。

## 计分（内部）

相关题均分：大于等于 1.4 为高，大于等于 0.7 为中，其余为低。

| 维度 | 题目 | 用户类型 |
| --- | --- | --- |
| 情感陪伴 | Q4、Q5 | A 陪伴型 |
| 家庭关系 | Q9、Q10 | B 家庭困扰型 |
| 情绪支持 | Q6、Q7、Q8 | C 情绪困扰型 |
| 社交连接 | Q11 | D 社交缺失型 |
| 兴趣生活 | Q12、Q13 | E 生活空心型 |
| 精神成长/意义 | Q13、Q14 | F 成长探索型 |

- 经常、经常有、经常会、很想、经常有这种感觉记 2 分；偶尔、有一点记 1 分；基本没有、很少、暂时没有记 0 分。
- Q8 反向：基本可以 0，有时很难 1，经常很难 2。
- Q11：经常联系 0，偶尔联系 1，基本没有 2。
- Q13 同时计入兴趣生活和精神成长/意义。
- Q15 勾选把对应维度抬一档，已经是高则不变。健康养生和兴趣活动都对应兴趣生活，同时勾选也只抬一档。学新东西对应精神成长/意义。
- 取抬升后的最高维度定类型。并列时：家庭 > 陪伴 > 情绪 > 意义 > 兴趣 > 社交。
- 若最高维度仍是低，结果页用「日子大体安稳」的说法。类型仍按并列规则写入数据，并注明不代表该项有明显需要。
- 内部标记只进飞书和本机数据：心情不太容易自己缓过来时，记为优先安排聊天倾听。页面不展示。

抽样自测：

```bash
node tests/scoring.test.js
```

## 配置飞书

编辑 `js/config.js`。地址留空时，提交仍然成功，结果页显示「已记录本次选择」，控制台不会报错。最近一次完整数据在本机 `localStorage` 键 `shenghuo-xinqing:last`。

默认 `FEISHU_WEBHOOK_MODE` 是 `"bitable"`。填好多维表格的地址后，请求体是 `{ "fields": { ... } }`。浏览器跨域失败时，数据留在 `shenghuo-xinqing:pending`，结果页可以「再试一次送出」。

### 方式一：群机器人

1. 打开飞书群 → 设置 → 群机器人 → 添加机器人 → 自定义机器人。
2. 复制 Webhook，形如 `https://open.feishu.cn/open-apis/bot/v2/hook/xxxxxxxx`。
3. 写入：

```js
FEISHU_WEBHOOK_URL: "https://open.feishu.cn/open-apis/bot/v2/hook/xxxxxxxx",
FEISHU_WEBHOOK_MODE: "bot",
```

4. 把 `index.html` 的 `?v=` 加一，提交并推到 `main`。
5. 可用下面的命令先确认地址本身可用（把地址换成你的）：

```bash
curl -X POST "https://open.feishu.cn/open-apis/bot/v2/hook/xxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{"msg_type":"text","content":{"text":"生活与心情小调查：连通测试"}}'
```

消息里包含：用户 ID、提交时间、年龄段、居住、生活状态、Q4～Q15、六维、核心需求 TOP3、用户类型、建议跟进、风险提示、需求总结。

### 方式二：多维表格自动化（默认）

1. 在多维表格中建立文本字段，字段名与下面完全一致：用户ID、提交时间、年龄段、居住、生活状态、Q4、Q5、Q6、Q7、Q8、Q9、Q10、Q11、Q12、Q13、Q14、Q15、六维、核心需求TOP3、用户类型、建议跟进、风险提示、需求总结。
2. 自动化选择「接收到 webhook 时」，复制地址。
3. 配置：

```js
FEISHU_WEBHOOK_URL: "自动化给你的 https 地址",
FEISHU_WEBHOOK_MODE: "bitable",
```

请求体是 `{ "fields": { "用户ID": "...", ... } }`。请按这个结构把字段映射进表格。

### 方式三：开放平台 API

把 `FEISHU_WEBHOOK_URL` 留空，填写 `FEISHU_BITABLE` 的 `appId`、`appSecret`、`appToken`、`tableId`。应用需要多维表格读写权限，并被加为该表协作者。

静态网页里的密钥所有访客都能看到，所以不要使用高权限密钥。更稳妥的是方式一或方式二。

送出失败时，结果页会轻声说明选择已留在本机，并出现「再试一次送出」。未成功的数据在 `shenghuo-xinqing:pending`。

## 页面上不要出现的说法

心理疾病、心理测评、抑郁测试、老年心理问题、精神状态评估、心理健康得分、诊断、焦虑症、抑郁症、心理咨询。

结果页用「聊天」「倾听」这类日常说法。不要在结果页写分数、等级字母或内部标记。

## 已知限制

- 纯静态页面，没有登录，也不能填写姓名或电话。
- 没有配置飞书时，数据只在填写者自己的浏览器里。
- 浏览器直接请求飞书可能被跨域策略拦住。群机器人在部分浏览器里能发出，若被拦住，页面仍给出结果，并保留数据供重试。确认地址时请用上面的 `curl`，或在飞书自动化、服务器侧接收。
- 开放平台密钥放在前端等于公开，只适合内部试验。
- 规则是固定文案，不会调用大模型改写总结。
- 内部标记只表示「建议优先安排聊天」，不是医疗判断。
- 刷新页面会从头开始；做完后的最后一次结果仍留在本机存储里。
